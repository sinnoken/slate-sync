# 精度理論與錄製秒數

這份文件說明場記板要錄多久、錄在哪裡，以及預期的誤差。數字是由分析器的誤差模型算出的理論值；測試檔的實測結果見 [testing.md](testing.md)。

## 誤差模型

分析器把每一秒的前緣（檔案時間）對真實時間做直線擬合，σ 是每個前緣的時間誤差（擬合殘差的標準差）。誤差估計與 `src/core/fit.js` 的 `uncPpm`（速度比例誤差）與 `predSe`（任一位置的預估誤差）相同：

```
速度比例誤差 = σ / √Sxx
任一位置 x 的誤差 = σ × √(1/n + (x − x̄)² / Sxx)
```

n 是讀到的秒數，x̄ 是它們的平均位置，Sxx 是各秒位置與 x̄ 的差的平方和。

- **頭尾都錄**（每端 n 秒，兩端相隔 T 秒）：速度比例誤差 ≈ σ·√2 / (T·√n)，檔案任何位置的最大誤差 ≈ σ / √n。兩端越遠，速度越準；位置誤差只看每端的秒數，與錄影長度無關。
- **只錄一端**（n 秒）：Sxx = n(n² − 1)/12，速度比例誤差 = σ / √Sxx，與錄影長度無關；位置誤差隨與該端的距離線性變大，在檔案另一端最大。

## σ 的假設

| 收音方式 | σ | 依據 |
|---|---|---|
| 線路輸入 | 0.01 ms | 測試檔的實測（[testing.md](testing.md)）；也是分析器的 σ 下限 |
| 空氣收音 | 0.9 ms | 一支真實手機錄影：手機喇叭播放、相機內建麥克風收音，讀到 9 秒，擬合殘差 0.88 ms |
| 只有畫面碼 | 一格 ÷ √12（30 fps 時 9.6 ms） | 邊緣只知道落在相鄰兩格之間，視為均勻分布 |

只有畫面碼時，相鄰各秒的取樣相位彼此相關，誤差不一定能平均掉；分析器另有下限，見 [visual-code.md](visual-code.md) 的「擬合與來源」。

## 最少秒數

除了精度，每端的秒數還決定分析器能讀出多少時間資訊（規則見 [waveform-code.md](waveform-code.md) 的解讀規則）：

| 每端讀到 | 得到的資訊 |
|---|---|
| 2 秒 | 只有一分鐘內的秒數 |
| 3 秒以上，且多數秒的音高一致 | 9 分鐘循環內的位置 |
| 錄過一個整分鐘（:00 秒）並加 `--minute`（網頁版勾選「尋找分鐘標記」） | 分鐘標記：一小時內的位置；與音高合併為 3 小時 |

- 頭尾模式要求兩端相隔 60 秒以上；更近時視為同一端。
- 各種資訊對應的跨檔案比對範圍見 [start-time.md](start-time.md) 的循環表。

## 未涵蓋的因素

以上是理論值，只含每個前緣的隨機誤差。下列因素不在其中：

- **非線性漂移**：設備時鐘的速率隨溫度變化（例如長時間錄影機身變熱）時，中段會偏離頭尾之間的直線。頭尾模式的誤差估計看不到這一點；可在中段再錄一次場記板，或用 `--full` 抽查。
- **傳播延遲**：聲音每公尺約 2.9 ms（343 m/s）。距離固定時是固定偏移，只影響起點，不影響速度比例；可用 `--distance` 扣除。
- **場記板本身的輸出延遲**：手機的聲音與畫面輸出延遲是固定偏移，可在場記板「設定 → 校準」補償；聲畫同步檢查的說明見 [visual-code.md](visual-code.md)。
