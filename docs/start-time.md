# 起點時鐘與跨檔案比對

同步訊號給出的是「循環中的位置」：只知道秒數時一分鐘一輪，加上音高或畫面碼時九分鐘一輪。這份文件規定分析器如何決定每個檔案的循環長度、如何用檔案內的建立時間補上時、分，以及跨檔案比對的範圍。

## 循環長度

每個檔案依讀到的資訊取最長的循環 M（秒）：

| 讀到的資訊 | M | 跨檔案比對範圍 |
|---|---|---|
| 只有秒數（讀不到音高時，例如只讀到 2 秒） | 60 | ±30 秒 |
| 波形碼的音高（[waveform-code.md](waveform-code.md)）或畫面碼的 tag（[visual-code.md](visual-code.md)） | 540 | ±4.5 分鐘 |
| 分鐘標記 | 3600 | ±30 分鐘 |
| 分鐘標記＋音高或 tag | 10800 | ±1.5 小時 |
| LTC（[ltc.md](ltc.md)） | 86400 | ±12 小時 |

兩個檔案比對時用兩者 M 的最大公因數；任一方的起點時鐘已由建立時間確定（下一節）時，改用確定的時鐘直接相減。對齊表與文字報告註明所用循環的比對範圍（上表；M = 3600 時不註明）。

比對所用的循環來自建立時間的時鐘，而相差超出「不含時鐘的最大公因數循環 M」的比對範圍（|差| > M/2）時，對齊表與文字報告同時列出依建立時間的差與循環內的差（wrap 到 ±M/2），並警告「依檔案建立時間判定起點相差 X 秒；若設備時鐘或時區設定錯誤，實際可能是 Y 秒（循環內的差）」。原因：建立時間只能在 M 循環內驗證，設備時鐘或時區差 M 的整數倍（M = 540 時例如 3、6、9、12 小時）照樣會通過下一節的檢查。

## 用檔案建立時間補上時鐘

### 來源
- MP4／MOV：`mvhd` 的 creation_time（UTC；MediaInfo 顯示為 Encoded date）。命令列版讀 ffprobe 的 `format_tags=creation_time`。
- WAV：BWF 的 `TimeReference`（從午夜起的取樣數，本地時間）。
- 檔案修改時間只用於顯示「時」的推測，標示「可能不準」，不用於比對。

### 判斷建立時間的意義
各家設備寫入的時間不同：有的是開始錄影的時間，有的是存檔（結束）的時間；有些相機把本地時間當成 UTC 寫入。設 C 為建立時間換算成的本地時間（午夜起秒數），C′ 為把 creation_time 的 UTC 時刻直接當成本地時間（本地時間被誤當 UTC 寫入時的讀法），L 為分析器量得的起點（循環中的位置，0 ≤ L < M），D 為檔案長度（秒）。四個候選：

```
r_start = wrap(C − L, M)        wrap(v, M) = v 換算到 [−M/2, M/2)
r_end   = wrap(C − D − L, M)
r′_start = wrap(C′ − L, M)      r′_end = wrap(C′ − D − L, M)
```

- 每個 r 先四捨五入到 1 ms，邊界不會因 µs 等級的量測誤差而翻轉。C′ 與 C 相同（本地時區為 UTC）時只算一種讀法。
- 恰好一個候選的 |r| ≤ 2 秒時採用：起點時鐘 = C − L（或 C′ − L）中最接近的 M 的整數倍 + L（結束型先減 D）。報告標示「依檔案建立時間（開始）」或「（結束）」，C′ 的讀法另註「本地時間寫成 UTC」，並列出 r（設備時鐘與場記板時鐘的差，正值表示設備較快）。
- 兩個以上通過（例如檔案長度剛好是 M 的整數倍，或時區偏移剛好是 M 的倍數：UTC+9 與 M = 540）時不採用，報告註明「有多種解讀都符合量得的起點」；都不通過時不採用，報告註明「與量得的起點不一致」。兩種情況都維持循環內的位置。這是失敗時保守的做法：分不出來就不猜。
- 建立時間不晚於 1970-01-01（0 或負的 Unix 時間）視為沒有建立時間。
- 只有 M 為 540 的倍數（540、10800）時採用的時鐘才用於跨檔案比對。M = 60 或 3600 時，設備時鐘差整數分鐘也會通過 2 秒的檢查，所以換算出的時間只顯示（報告註明「只供顯示，不用於跨檔案比對」），比對仍用循環內的位置。
- BWF 的 `TimeReference` 一律視為開始時間、本地時間（規格如此），只檢查 r_start。

### 用途
- 顯示完整的起點與結束時間（時:分:秒）。
- 跨檔案比對：兩個檔案的起點時鐘都已確定且可用於比對（M 為 540 的倍數）時，直接用時鐘相減（M = 86400，比對範圍 ±12 小時；不比較日期）；只有一方確定時，仍用最大公因數的循環。

## 驗收
- 測試產生器可寫入建立時間（開始型、結束型、時鐘偏差 ±1.5 秒與 ±5 秒），分析器的判斷與起點時鐘全部正確；偏差 5 秒時不採用並註明。
- 回歸測試（`tests/check_core.js`）：兩檔真實相差 5 秒、其中一檔設備快 60 秒、M = 60 時不用於比對，差值為 5 秒；UTC+9 本地時間寫成 UTC、M = 540 時不採用；r = +2.000001 秒四捨五入後採用；設備快 9 分鐘、時區差 3 小時（M = 540）時同時列出循環內的差，相差在範圍內時不列。
- 兩個檔案起點相差 20 分鐘、只有波形碼音高（M = 540）時，有建立時間即可正確比對；沒有建立時間時報告的差值為 20 分鐘 mod 9 分鐘的結果，並在報告中註明比對範圍。
