# 起點時鐘與跨檔案比對

同步訊號給出的是「循環中的位置」：只知道秒數時一分鐘一輪，加上音高或畫面碼時九分鐘一輪。這份文件規定分析器如何決定每個檔案的循環長度、如何用檔案內的建立時間補上時、分，以及跨檔案比對的範圍。

## 循環長度

每個檔案依讀到的資訊取最長的循環 M（秒）：

| 讀到的資訊 | M | 跨檔案比對範圍 |
|---|---|---|
| 只有秒數（舊版場記板的波形碼） | 60 | ±30 秒 |
| 波形碼的音高（[waveform-code.md](waveform-code.md)）或畫面碼的 tag（[visual-code.md](visual-code.md)） | 540 | ±4.5 分鐘 |
| 分鐘標記 | 3600 | ±30 分鐘 |
| 分鐘標記＋音高或 tag | 10800 | ±1.5 小時 |
| LTC（[ltc.md](ltc.md)） | 86400 | 不限（同一天內） |

兩個檔案比對時用兩者 M 的最大公因數；任一方的起點時鐘已由建立時間確定（下一節）時，改用確定的時鐘直接相減。

## 用檔案建立時間補上時鐘

### 來源
- MP4／MOV：`mvhd` 的 creation_time（UTC；MediaInfo 顯示為 Encoded date）。Python 版讀 ffprobe 的 `format_tags=creation_time`。
- WAV：BWF 的 `TimeReference`（從午夜起的取樣數，本地時間）。
- 檔案修改時間只用於顯示「時」的推測，標示「可能不準」，不用於比對。

### 判斷建立時間的意義
各家設備寫入的時間不同：有的是開始錄影的時間，有的是存檔（結束）的時間。設 C 為建立時間換算成的本地時間（午夜起秒數），L 為分析器量得的起點（循環中的位置，0 ≤ L < M），D 為檔案長度（秒）：

```
r_start = wrap(C − L, M)        wrap(v, M) = v 換算到 [−M/2, M/2)
r_end   = wrap(C − D − L, M)
```

- 恰好一個的 |r| ≤ 2 秒時採用：起點時鐘 = C − L 中最接近的 M 的整數倍 + L（結束型先減 D）。報告標示「依檔案建立時間（開始）」或「（結束）」，並列出 r（設備時鐘與場記板時鐘的差，正值表示設備較快）。
- 兩個都 ≤ 2 秒（例如檔案長度剛好是 M 的整數倍）或都 > 2 秒時不採用，報告註明「建立時間與量得的起點不一致」，維持循環內的位置。
- BWF 的 `TimeReference` 一律視為開始時間（規格如此），只檢查 r_start。

### 用途
- 顯示完整的起點與結束時間（時:分:秒）。
- 跨檔案比對：兩個檔案的起點時鐘都已確定時，直接用時鐘相減，不受上表比對範圍限制；只有一方確定時，仍用最大公因數的循環。

## 驗收
- 測試產生器可寫入建立時間（開始型、結束型、時鐘偏差 ±1.5 秒與 ±5 秒），分析器的判斷與起點時鐘全部正確；偏差 5 秒時不採用並註明。
- 兩個檔案起點相差 20 分鐘、只有波形碼音高（M = 540）時，有建立時間即可正確比對；沒有建立時間時報告的差值為 20 分鐘 mod 9 分鐘的結果，並在報告中註明比對範圍。
