# 驗證方式與結果

## 自行驗證

```bash
python tests/make_test_media.py test-media/a.wav --minutes 4 --ppm 833
python tests/make_test_media.py test-media/b.mp4 --minutes 4 --ppm -694 --start 12:35:00.039 --plug 70
python python/slate_sync.py test-media/a.wav test-media/b.mp4
```

生成器會印出設定的速度比例與真實長度，與分析結果比對即可。網頁版分析器請用本機伺服器開啟（WebCodecs 需要安全環境）：

```bash
python -m http.server 8000      # 在 repo 根目錄執行，然後開啟 http://localhost:8000/web/sync-analyzer.html
```

## 已驗證項目

所有測試檔的時鐘偏差為 +833、−694 或 +200 ppm，長度 4–10 分鐘。

### 解碼與計算（Python 版）

| 情況 | 結果 |
|---|---|
| WAV、AAC（M4A）、MP4、MPEG-TS | 速度比例誤差 ≤ 0.06 ppm，相對位置誤差 ≤ 0.006 ms |
| 產生器只接頭尾，聲道在頭尾不同 | 正確 |
| 開頭 40 秒沒有波形碼（需往內搜尋） | 正確 |
| 音訊軌比畫面軌晚 28 ms 開始 | 正確（修正前速率誤差 118 ppm） |
| MPEG-TS 起點 1.4 秒、畫面晚 21 ms | 與同內容 MP4 一致 |
| 波形碼由網頁本身的產生程式輸出 | +833.1 ppm，起點 12:34:56.789 |

### 自動同步相容性

模擬剪輯軟體以音訊相關性自動同步：每秒變換載波頻率後，錯開 1 秒時的相關度由 92–97% 降為 0–3%。

| 情況 | 結果 |
|---|---|

| CPU 降速 6 倍 | 無掉幀 |

### 以手機喇叭播放、麥克風收音

以房間脈衝響應模擬（直達／迴響比依臨界距離估算），頭尾各約 65 秒有波形碼：

| 距離 | 客廳 60 m³ 安靜／小聲交談 | 辦公室 150 m³ | 大空間 1500 m³ |
|---|---|---|---|
| 0.3 m | ✓／✓ | ✓／✓ | ✓／✓ |
| 0.5 m | ✓／✓ | ✓／✓ | ✓／✓ |
| 0.75 m | ✓／✓（僅讀到 5 秒） | ✓／✓ | ✓／✓ |
| 1 m | ✓／✗ | ✓／✓ | ✓／✓ |

讀得到時，速率誤差 ≤ 2.2 ppm、起點誤差 ≤ 0.04 ms（不含每公尺約 2.9 ms 的聲音傳播延遲）。另以 3–5 m 與迴響長的大廳測試，多數讀不到；延長脈衝間隔（「空氣傳播模式」）只對 1–3 m 的安靜房間有幫助，因此未採用。

此測試同時發現並修正一個錯誤：開頭讀到分鐘標記、結尾沒有時，兩端合併換算會把開頭約 60 秒的範圍折疊，產生錯誤但看似正常的結果。現已修正，並加上防護：速率偏差超過 1% 或擬合殘差超過 5 ms 時判定為讀取錯誤，不輸出結果。

### 長時間錄影與基準檔對齊

| 情況 | 結果 |
|---|---|
| 1 小時、時鐘偏差 ±0.9%（累積約 32 秒）、無分鐘標記 | 舊版算成反方向（−7724 ppm）；新版 ±9000.000 ppm，起點正確 |
| 以 a 為基準對齊 b、c、d（不同漂移與起點） | 起點誤差 ≤ 0.011 ms，播放速度誤差 ≤ 0.07 ppm |
| 換算 b 的 100 秒到 a | 103.405509 秒（理論值 103.405513） |

### 模式與適應式讀取

| 情況 | 模式 | 結果 |
|---|---|---|
| 頭尾各 30 秒 | 頭尾 | 每端只讀約 7 秒即達 ±0.004 ms |
| 只有開頭／只有結尾 | 僅開頭／僅結尾 | 速率誤差 0.33 ppm，預估 ±0.084 ms |
| 20 分鐘，+800 → +1000 ppm（機身變熱），整段有碼 | 頭尾 | 長度正確，但中段實際偏離直線約 30 ms |
| 同上，`--full`（抽查 3 處） | 全段 | 偵測到非線性，分 4 段；中段實際誤差 2.3 ms（預估 2.7） |
| 同上，`--probe 7` | 全段 | 分 8 段；中段實際誤差 0.77 ms（預估 0.83） |
| 線性漂移，`--full` | 全段 | 中段偏差 0.010 ms，判定不需分段 |
| 網頁版與 Python 版（上列各情況） | — | 模式、速率、起點、分段結果一致 |

### 用上每秒所有脈衝的前緣

每秒除了同步脈衝，數字脈衝的起點也是固定的；場記板每秒用一個從零相位開始的振盪器，所以每個脈衝開啟時的波形位置可由音高與時間位置算出。分析器把每秒所有脈衝換算回該秒起點後平均，並自動比較：每秒時間的離散度較小的算法才採用。

| 只錄一端 11 秒，各 12 次 | 只用同步脈衝 | 用上所有脈衝 |
|---|---|---|
| 乾淨 | 0.23 ppm | 自動改用同步脈衝（結果相同） |
| 雜訊 SNR 20 dB | 64.8 ppm（最大 188） | 24.3 ppm（最大 77） |
| 迴響（約 0.5 m） | 16.2 ppm | 16.5 ppm（迴響影響同一秒的所有脈衝，平均無幫助） |

測試產生器同時修正為和場記板一致：每秒一個振盪器開關出各脈衝，且整秒依錄音設備的時鐘比例縮放（包括音高與脈衝間隔）。所有模式的回歸測試與網頁版、Python 版比對皆一致。

### 手機 App（PWA）

以本機伺服器測試：App 資訊與四種圖示可讀取，Service Worker 啟用並快取所有檔案；斷網後重新開啟場記板與首頁皆正常，時鐘照常運作。

### LTC 輸出

以場記板本身的程式產生 29.97 DF、29.97 NDF、25 fps 的 LTC，再以獨立解碼器讀回：丟格規則（每分鐘跳過 ;00、;01，每 10 分鐘不跳）、極性位元與跨區塊連續性皆正確。

### 多語言介面

以 Edge 無頭模式驗證三個網頁的繁體中文、English、日本語、한국어：

- 四種語言的字串 key 完全相同、插值變數一致，程式與標記用到的 key 都有定義（以腳本比對）。
- 繁中介面與加入多語言前相同：場記板七種畫面的 DOM 文字比對無差異；分析器分析同一組 WAV，文字報告逐字相同。
- 切換語言不重新載入頁面，倒數照常進行，狀態列、排程預覽與已完成的分析結果即時改用新語言。
- 360 × 640、390 × 844 直拿與 667 × 375 橫拿下，四種語言的按鈕與文字都沒有溢出。
- 場記板 CSS 整併前後，固定時間的 11 種畫面逐像素比對完全相同。
